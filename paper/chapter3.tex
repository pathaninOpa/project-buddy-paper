\chapter{METHODOLOGY}
\hspace{\parindent} 
This section describes the methodology for developing the smart companion system for elderly care. The methodology comprises system design, data collection, pre-processing techniques, machine learning methods, hyperparameter configurations, and performance evaluation. The technical methods used in this study include speech recognition, natural language processing, sentiment analysis, and real-time video intercommunication. Each stage of the methodology is explained to ensure clarity and reproducibility.

\noindent\textbf{Key Components:}
\begin{itemize}
	\item Tablet Application: Captures speech and visual data.
	\item Mobile Application: Allows monitoring and communication with hardware users.
	\item Speech Recognition: Faster Whisper model for offline, high-accuracy Thai speech recognition.
	\item API Server: FastAPI server to handle tokenization and requests.
	\item Local LLM: GEMMA 3 for emotion classification and dialogue generation.
	\item Text-to-Speech: Google Text to Speech API converts the model responses into audio feedback.
	\item Video Call System: ZegoCloud SDK for stable, low-latency video communication.
	\item Database Systems: Firebase for user information, chat history, emotion history, reminder
\end{itemize}
%================= Data =========================================
\section{Data}
{ 
	\setlength{\leftskip}{1cm}
	\setlength{\parindent}{2.5em}
	The system relies on audio and visual data collected from elderly users during natural conversations. Audio data is captured using microphones embedded in the hardware client, while visual data is captured through cameras for real-time video communication. The collected audio data is processed for speech transcription, while text data is processed for emotion recognition and conversation generation.
	\par
}
\textbf{Data Processing}
\begin{itemize}
	\item Audio Transcription: Faster Whisper performs automatic speech recognition (ASR) to convert spoken Thai into text with high accuracy.
	\item Text Tokenization: Transcribed user inputs are tokenized and filtered (e.g., removing non-speech artifacts) before being processed by the LLM for emotion classification and response generation.
\end{itemize}

\subsection{Caretaker Application}
\subsubsection{UI/UX Design}
{ 
	\setlength{\leftskip}{1.8cm}
	\setlength{\parindent}{5em}
	The application was created with a heavy focus on simplicity and usability because the caregiver is the applications main user and needs quick and dependable access to important data. In order to visualize the interface structure and interaction flow early on, the design approach started with wireframing using Figma. In order to guarantee that important data could be retrieved effectively, considerable attention was paid to layout organization, visual hierarchy, and user navigation throughout this phase. To ensure uniformity throughout the application and to cut down on superfluous complexity, each page was thoroughly described, allowing caregivers to complete critical tasks with little effort and learning time.
	\par
}

{ 
	\setlength{\leftskip}{1.8cm}
	\setlength{\parindent}{5em}
	To give caregivers an easy to understand summary of the care recipient's emotional state throughout the day, an emotion analysis dashboard was created. A recent mood card, an aggregated emotion summary, and a thorough conversation log documenting exchanges between the care recipient and the Buddy app. The dashboard includes visual components like data cards and graphs that show emotion trends over time to improve interpretability. A unique equation built into the care receiver program is used to calculate these patterns, which will be covered in a later section. To assist everyday caring tasks, a reminder scheduling interface was created in addition to emotional monitoring. This interface makes it simple for caregivers to create, manage, and update reminders for the care recipient. When combined, these characteristics give caregivers useful skills and emotional insights to enable prompt and consistent treatment.
	\par
}

\newpage
{ 
	\setlength{\leftskip}{1.8cm}
	\setlength{\parindent}{5em}
	To guarantee a seamless and intuitive user experience, accessibility and simplicity were heavily prioritized during the design phase. The application's user journey was thoughtfully designed to minimize complexity and decrease the mental strain needed to complete essential tasks. Caretakers can easily comprehend and access key functions thanks to the clear visual hierarchy, accessible font, and consistent navigation patterns used in the design of each screen and interaction. The program makes it possible for caregivers to use the system with confidence and effectiveness in a variety of scenarios by emphasizing simple processes and accessible design concepts.

\subsubsection{Frontend Implementation}
{ 
	\setlength{\leftskip}{1.8cm}
	\setlength{\parindent}{5em}
	Using Flutter as the primary framework and Dart as the programming language, the application's frontend was created. This strategy preserves a consistent user interface and interaction experience while enabling the program to function seamlessly across platforms. Several important displays make up the frontend, each of which is intended to facilitate particular user tasks and workflows. Together, these panels help users manage identification, onboarding, daily monitoring, communication, and analysis functions. This ensures that the whole experience is responsive, straightforward, and simple for caregivers to use on a regular basis.
	\par
}

{ 
	\setlength{\leftskip}{1.8cm}
	\setlength{\parindent}{5em}
	The application's visual tone was taken into consideration in addition to its practical design. The Buddy app has a pleasant pastel color palette that combines light blue and light purple to create a serene and soothing ambiance. In a caring setting when users may already be under emotional or mental strain, this color scheme was purposefully chosen to seem cozy, welcoming, and non threatening. While preserving readability and clarity, the pastel colors soften the interface and make it feel less clinical and more friendly. The application's design strives to provide a feeling of comfort and mental safety by utilizing this subdued purple blue color scheme throughout. This way, caregivers can concentrate on providing care and keeping an eye on things without being distracted by the interface.
	\par
}

\begin{enumerate}[leftmargin=2.2cm]
	\item Login page:
	\begin{enumerate}[label=\alph*.] 
		\item For a safe and easy login process, the application incorporates Firebase Authentication with Google Sign In. By enabling users to access the application with their current Google accounts, this method simplifies the authentication procedure and eliminates the need to create and maintain unique credentials. When a user successfully logs in for the first time, the system displays an onboarding pop up that asks a series of simple questions intended to collect crucial profile data and gain a deeper understanding of the person. This first interaction improves usability and engagement immediately.
	\end{enumerate}
	
	\item Home page:
	\begin{enumerate}[label=\alph*.] 
		\item The app allows you to add new Buddies and displays a list of current ones connected to the caregiver. When the Add Buddy button is pressed, a pop up form that requests basic information about the care receiver who will be using the Buddy application appears. This information is collected to ensure accurate identification in the system and to build a preliminary profile for the care receiver. The unique buddy code will be generated and shown on the screen following the buddy's successful creation. In order to safely connect both sides of the system, the caregiver can copy this code and provide it to the care receiver, who can then paste it into the care receiver application. A controlled and dependable pairing mechanism between caregiver and care receiver devices is ensured by this approach.
	\end{enumerate}
	
	\item Buddy detail page :
	\begin{enumerate}[label=\alph*.] 
		\item A number of essential components are displayed on the main screen to facilitate caregivers' fast and simple interaction. These include easily visible buttons for video calling, reminders, emotion analysis, and information access, as well as the most current mood card, which provides an instantaneous snapshot of the care recipient's most recent emotional state. Caregivers may check emotional updates, start contact, create reminders, view analytics, or access profile information without having to navigate across many screens thanks to the features' convenient placement and recognition. This arrangement makes it possible to carry out crucial tasks with assurance and speed, particularly in circumstances where quick reactions are required.
	\end{enumerate}
	
	\item Analytics page :
	\begin{enumerate}[label=\alph*.] 
		\item The analytics section presents selected elements to assist caregivers in comprehending the care recipient's emotional condition. These consist of a 4-Hour Emotion Trend, an Overall Emotional Snapshot, Emotion Counts Today, and a Comprehensive Message Log. The comprehensive message log, daily emotion counts, and overall emotional snapshot are all taken straight from Firebase, guaranteeing that the data displayed is current and represents the most recent exchanges. When more in depth context is required, these components enable caregivers to quickly analyze emotional trends, track the frequency of specific emotions throughout the day, and look at message level information. Additionally, the 4-Hour Emotion Trend presents the data in an easy to read line chart, giving a visual summary of how emotions evolve over time. When combined, these elements provide both high level insights and specific information, assisting caregivers in making quicker and more informed decisions.
	\end{enumerate}
	
	\item Reminder page :
	\begin{enumerate}[label=\alph*.] 
		\item A calendar card, an announced card, a waiting card, and an Add Reminder button are among the essential components that the reminder screen shows to assist caregivers in efficiently managing planned activities. These cards give a concise summary of scheduled events, previously announced reminders, and pending ones. The user is directed to a special Add New Event page when they click the Add Reminder button. Before saving the reminder, the caregiver can input the event's title, description, date, and time on this page. Caregivers may rapidly generate and manage reminders without needless steps thanks to this simple and easy to follow approach, which also ensures that crucial information is accurately captured. 
	\end{enumerate}
	
	\item Video call UI :
	\begin{enumerate}[label=\alph*.] 
		\item The ZegoCloud video call interface shows on the screen automatically when the video call button is pressed. With no further setup on the part of the user, this interface enables real time video calling between the caregiver and the care recipient. Users can initiate a video call fast and effortlessly thanks to the application's seamless transition to the call interface. This feature facilitates direct, actual interaction, which helps caregivers maintain a more immediate and intimate connection with care receiver
	\end{enumerate}
	
\end{enumerate}

\subsection{Chatbot pipeline: Data  Flow and Processing}
{ 
	\setlength{\leftskip}{1cm}
	\setlength{\parindent}{2.5em}
	This section Tells the Data flow and processing within the shared board pipeline, from raw input ingestion to generated responses and caretaker insights, reflecting the implemented system architecture and code.
	\par
}

\subsubsection{Data Collection and Ingestion}
	\begin{itemize}
		\item Audio Input: Raw audio streams are continuously captured from the hardware client's microphone.
		\item Transcription: Faster Whisper model processes the captured audio to accurately transcribe spoken Thai into text (transcribedText). This text forms the primary input for the conversational agent.
		\item Conversation History: The transcribed user utterances, along with the chatbot's previous responses, are maintained as a dynamic conversation history for the Large Language Model to ensure contextual understanding.
		\item Emotion Logs: Emotion classifications (detectedEmotion) are inferred by the LLM (specifically GEMMA 3:1b, as detailed in Section 3.3 Methods) for each relevant turn of the conversation.
		\item Local LLM: GEMMA 3 for emotion classification and dialogue generation.
		\item Metadata Collection: Timestamps and unique session IDs are automatically associated with each interaction and data point for logging and analysis.
		\item Data Storage: User information is stored in PostgreSQL. Raw chat history (including transcribed text, detected emotions, timestamps, and session IDs) is stored in MongoDB for dialog history, and corresponding dialog embeddings are managed in Pinecone. Mood summaries derived from conversations are stored in Firebase.
	\end{itemize}
\newpage
\subsubsection{Data Preprocessing and Contextualization}
\begin{itemize}
	\item Audio Input: Raw audio streams are continuously captured from the hardware client's microphone.
	\begin{itemize}
		\item High-pass filtering (cutoff at 100 Hz) to remove low-frequency background noise.
		\item Normalization (target RMS 0.1) to standardize audio amplitude.
		\item Voice Activity Detection (WebRTCVAD Mode 1) to accurately identify and isolate speech segments from silence.
		\end{itemize}
	\item Language Filtering (for STT): Transcribed text is subjected to a language probability check to ensure it predominantly contains Thai characters, minimizing the impact of potential transcription errors of hallucinations.
	\item Text Tokenization (for LLM): Transcribed user inputs are tokenized and, if necessary, further filtered to prepare them for efficient processing by the LLM.
	\item Contextual Formatting (for LLM): Each user input and system response is formatted with appropriate roles (user, system, assistant) and appended to the conversationHistory to maintain coherent dialogue context for the LLM.
\end{itemize}

\subsubsection{Large Language Model (LLM) Operations}
\begin{itemize}
    \item \textbf{Dialogue Generation:} The gemma3:4b model, accessed via the Ollama API, serves as the core of the chatbot, responsible for generating contextually relevant and engaging conversational responses.
    \item \textbf{Emotion Classification:} Integrated within the LLM’s processing, the system implicitly classifies the user’s emotional state based on their transcribed input and conversational nuances.
    \item \textbf{Persona Adherence:} The LLM’s system prompt ensures responses adhere to a predefined elderly companion persona, characterized by:
    \begin{itemize}
        \item Primary use of the Thai language, with English transliteration allowed when necessary only.
        \item A casual, natural, and family-like conversational tone.
        \item Avoidance of formal polite particles (Ka/Krub) at the end of sentences.
        \item Emphasis on clear, concise, and easily understandable advice.
        \item Strict adherence to a maximum response length of 6 sentences to ensure brevity for spoken output.
    \end{itemize}
    \item \textbf{Response Constraints:} The `num\_predict` parameter for Ollama API is set to `4096` tokens, to ensure that the model will not get stuck with just the historical context.
\end{itemize}

\subsubsection{Caretaker Interaction Features}
\begin{itemize}
    \item \textbf{Mood Summary Generation:} The GEMMA 3:1b model processes conversation data to categorize a set range of emotion such as [Neutral, Happy, Relax, Sad, Pain, Anxiety, Angry] of the elderly user. These moods are stored in the Firebase database for caretaker review.
    \item \textbf{Reminder System:} Caretakers utilize the mobile application to schedule and manage reminders (e.g., for medication times or appointments). These scheduled reminders are synchronized with the backend, and the chatbot subsequently announces them aloud to the elderly user at the designated times using the Text-to-Speech system.
    \item \textbf{Caretaker Call Initiation:} Elderly users can directly initiate a video call to their registered caretaker through a specific voice command (e.g., “Call grandchild”). Upon detecting the user’s intent, the chatbot automatically initiates the video call connection using the ZegoCloud SDK, enabling seamless communication.
\end{itemize}

\section{Performance Evaluation}

The performance of the smart companion system will be evaluated based on the following metrics:

\subsection{Emotion Recognition Accuracy}

Emotion recognition accuracy will be measured using standard classification evaluation metrics:

\begin{itemize}
	\item \textbf{Confusion Matrix}: A table comparing predicted emotions against actual labels. It consists of:
	\begin{itemize}
		\item \textbf{True Positive (TP)}: Correctly predicted positive instances.
		\item \textbf{False Positive (FP)}: Incorrectly predicted positive instances.
		\item \textbf{True Negative (TN)}: Correctly predicted negative instances.
		\item \textbf{False Negative (FN)}: Incorrectly predicted negative instances.
	\end{itemize}
	\item \textbf{Precision, Recall, and F1-Score}:
	\begin{itemize}
		\item \textbf{Precision} = $\frac{TP}{TP + FP}$
		\item Measures the proportion of correctly predicted positive instances among all predicted positive instances.
		\item \textbf{Recall} = $\frac{TP}{TP + FN}$
		\item Measures the proportion of correctly predicted positive instances among all actual positive instances.
		\item \textbf{F1-Score} = $2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$
		\item The harmonic mean of precision and recall, balancing both metrics.
	\end{itemize}
	\item \textbf{Overall Accuracy}:
	\begin{itemize}
		\item $\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}$
		\item Measures the overall correctness of the model by considering both positive and negative instances.
	\end{itemize}
\end{itemize}

\subsection{Dialogue Generation Quality}

The evaluation of the model's ability to generate coherent and relevant responses is primarily conducted using an "LLM-as-Judge" methodology, complemented by human evaluation. This approach leverages a superior language model to assess the semantic quality of generated text, which correlates better with human judgment than traditional n-gram metrics.

\begin{itemize}
	\item \textbf{LLM-as-Judge (Gemini-2.5-Flash)}:
	\begin{itemize}
		\item A high-capability cloud model serves as the evaluator for responses generated by the local \textbf{Gemma 3:4b} model.
		\item \textbf{Scoring Scale}: Responses are rated on a scale of 1-10.
		\item \textbf{Evaluation Dimensions}:
		\begin{itemize}
			\item \textbf{Clarity}: Measures linguistic correctness and ease of comprehension.
			\item \textbf{Relevance to Elderly}: Assesses the appropriateness of the tone and content for the target demographic.
			\item \textbf{Conciseness}: Evaluates the efficiency of information delivery, prioritizing brevity for audio output.
		\end{itemize}
	\end{itemize}
	\item \textbf{Human Evaluation}:
	\begin{itemize}
		\item \textbf{Mean Opinion Score (MOS)}: Human participants rate interactions on a 1-5 scale.
		\item \textbf{Criteria}: Coherence, Fluency, Empathy, and Overall Satisfaction.
	\end{itemize}
\end{itemize}

\subsection{Speech-to-Text (STT) Performance}

The accuracy of the Thai speech-to-text module (Faster Whisper) will be evaluated using:

\begin{itemize}
	\item \textbf{Word Error Rate (WER)}:
	\begin{itemize}
		\item $\text{WER} = \frac{S + D + I}{N}$
		\item where $S$ = substitutions, $D$ = deletions, $I$ = insertions, and $N$ = total words in reference text.
	\end{itemize}
	\item \textbf{Character Error Rate (CER)}:
	\begin{itemize}
		\item $\text{CER} = \frac{S + D + I}{N}$
		\item where $N$ represents total characters in reference text, useful for Thai language without explicit word boundaries.
	\end{itemize}
\end{itemize}


\subsection{Video Call Quality}

The reliability and quality of the real-time communication feature, powered by the ZegoCloud SDK, are assessed against industry-standard benchmarks for telecommunication.

\begin{itemize}
	\item \textbf{Connection Success Rate}: The percentage of call attempts that successfully establish a peer-to-peer connection.
	\item \textbf{Average Latency}: The end-to-end delay (measured in milliseconds) between the audio/video capture on one device and its playback on the other. This is critical for maintaining a natural conversation flow.
	\item \textbf{Call Stability}: The ability of the system to maintain a continuous connection without drops or significant quality degradation over an extended period (e.g., >10 minutes).
	\item \textbf{Packet Loss Tolerance}: The system's resilience to network instability, specifically its ability to maintain audio intelligibility and video clarity despite packet loss.
\end{itemize}

\subsection{Software Testing and Validation}

To ensure the robustness and usability of the mobile application and backend services, a comprehensive testing strategy is employed, encompassing both functional and structural verification, as well as quantitative usability assessment.

\begin{itemize}
	\item \textbf{Black Box Testing}:
	\begin{itemize}
		\item \textbf{Functional Testing}: Verifies that all application features (e.g., login, call initiation, dashboard updates) function as specified in the requirements without knowledge of the internal code structure.
		\item \textbf{User Acceptance Testing (UAT)}: Real users from the target demographic perform typical tasks to validate the system's usability and effectiveness in real-world scenarios.
	\end{itemize}
	\item \textbf{White Box Testing}:
	\begin{itemize}
		\item \textbf{Unit Testing}: Validates individual components and functions (e.g., API endpoints, database queries) to ensure they produce correct outputs for given inputs.
		\item \textbf{Integration Testing}: Verifies that different modules (e.g., the mobile app and the API server) interact correctly and data flows seamlessly between them.
	\end{itemize}
	\item \textbf{System Usability Scale (SUS)}:
	\begin{itemize}
		\item A standardized 10-item questionnaire used to assess the perceived usability of the system.
		\item Participants rate each item on a 5-point Likert scale (1 = Strongly Disagree, 5 = Strongly Agree).
		\item The final score ranges from 0 to 100, providing a global measure of system usability, where a score above 68 is typically considered "above average".
	\end{itemize}
\end{itemize}
